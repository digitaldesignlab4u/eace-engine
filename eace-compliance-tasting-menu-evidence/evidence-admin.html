EACE.AI — EVIDENCE ADMIN TOOL

Two offline, standalone utilities for Evidence Mode — generating the organisation keypair (Grade 2) and verifying an evidence record (Grade 1 or 2). Neither tab makes a network request; everything here runs locally in this browser tab.

Offline verification for Evidence Mode records (grade: local or attested). This is a separate check from the existing completion-receipt decoder — receipts and evidence objects are different artifact types with different trust guarantees; do not conflate their results.

Leave blank if you only need to verify Grade 1 (Local Evidence) records, or if you haven't deployed org attestation yet. Use the "Generate Organisation Key" tab to create one.

This tool performs cryptographic and structural checks only — it does not confirm the named person's real-world identity, and a Grade 1 (Local Evidence) verdict does not mean an organisation attested to this record. Read every check's note, not just the pass/fail badge. Evidence Mode records are a stronger artifact than the product's completion receipt, but "stronger" is not "absolute" — see README.md for the full trust model.

Generates the ECDSA P-256 keypair an organisation uses to co-sign Grade 2 (Attested Evidence) records. Runs entirely in this browser tab — the keypair is generated locally and never sent anywhere by this page.

Run this ONCE, on a machine HR/IT actually trusts, then close the tab. This page does not save anything — if you navigate away before copying both keys out, they are gone and you generate a new pair. The PRIVATE key below is the organisation's entire signing authority for Grade 2 evidence: anyone who has it can attest records on the organisation's behalf. Store it like any other organisational secret (a password manager, an HSM if you have one, or at minimum an encrypted, access-controlled file) — never commit it to source control, and never put it anywhere a browser or web server can serve it to the public. This product has no key-rotation or revocation mechanism built in; if this key is compromised, that is a manual incident-response problem for your organisation to handle, the same as any other leaked signing key.
